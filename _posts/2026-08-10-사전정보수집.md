# 2. 애플리케이션 아키텍처 파악 (2-tier / 3-tier)

## 2-tier

> DB 서버와 직접 연결하여 통신하며, DB에서 응답된 데이터를 기반으로 프로그램이 동작함

**확인 방법**
- [ ] Wireshark로 SQL 쿼리 요청이 평문으로 캡쳐되는지 확인
- [ ] 목적지 포트가 `1433`(MSSQL), `3306`(MySQL), `1521`(Oracle) 등 DB 포트인지 확인
- [ ] Import Table에 `System.Data.SqlClient`, `msado15.dll`, `odbc32.dll` 등 DB 드라이버 존재 여부 확인
- [ ] 설정파일 내 `Server=`, `Data Source=`, `Uid=`, `Pwd=` 등 DB 연결 문자열 존재 여부 확인

**결과 처리**
-> 위 항목이 확인되면 2-tier로 판단, DB 드라이버/연결 문자열을 기반으로 직접 DB 접근 가능 여부를 점검

## 3-tier

> 애플리케이션 서버와 연결하며, 요청 전송 시 서버가 대신 DB와 통신하여 반환된 데이터를 기반으로 프로그램이 동작함

**확인 방법**
- [ ] Wireshark로 SQL 문이 아닌 API 요청/응답 포맷(JSON, XML 등)인지 확인
- [ ] 설정 파일에 `https://api.company.com/v1`처럼 API 엔드포인트만 존재하는지 확인
- [ ] Import Table에 DB 드라이버 없이 `WinInet.dll`, `Winhttp.dll`, 소켓 API(`Ws2_32.dll`)만 존재하는지 확인

**결과 처리**
-> 위 항목이 확인되면 3-tier로 판단, API 엔드포인트 대상 요청/응답 조작 위주로 점검 방향 설정

# 3. 사용 기술/프레임워크 파악 (.NET, C++, Java 등)

> 사용된 언어/프레임워크에 따라 이후 분석에 사용할 도구가 달라지므로 우선 파악이 필요함

**확인 방법**
- [ ] DIE로 대상 실행 파일(exe/dll) 분석
- [ ] 결과에 `.NET` 문자열이 출력되는지 확인
- [ ] 확장자가 `.jar`이거나 DIE 결과에 `Java` 문자열이 출력되는지 확인
- [ ] 위 두 경우가 아니면 Native로 판단
- [ ] DIE의 file type 결과로 `32bit`/`64bit` 아키텍처 확인

**결과 처리**
-> `.NET` 확인 시 dnSpy 사용
-> `Java` 확인 시 JD-GUI 사용
-> Native 확인 시 IDA 또는 Ghidra 사용 (32/64bit 아키텍처에 맞춰 설정)

# 4. 네트워크 통신 방법 확인

> 통신 방식(프로토콜, 피닝 여부, 커스텀 프로토콜 여부)에 따라 트래픽을 가로채고 조작할 도구/방법이 달라지므로 사전 확인이 필요함

**확인 방법**
- [ ] Wireshark로 네트워크 패킷을 캡쳐하여 사용 프로토콜(HTTP/HTTPS/커스텀 TCP·UDP 등) 확인
- [ ] HTTPS인 경우 인증서 피닝 적용 여부 확인 (프록시 설정 시 통신 실패/에러 발생 여부로 판단)

**결과 처리**
-> `HTTP` 또는 피닝이 없는 `HTTPS` 확인 시 Burp Suite로 트래픽 가로채기
-> 피닝이 있는 `HTTPS` 확인 시 Frida로 피닝 우회 후 Burp Suite로 트래픽 가로채기
-> 커스텀 TCP/UDP 프로토콜 확인 시 Echo Mirage 또는 API 후킹 방식으로 트래픽 가로채기
