# 1. 정보 수집

## 점검 도구
- DIE (https://github.com/horsicq/DIE-engine/releases)
---
<br>

## 1.1. 애플리케이션 아키텍처 파악 (2-tier / 3-tier)
### 2-tier
```
DB 서버 자체와 연결하여 통신하며 DB에서 응답된 데이터를 기반으로 프로그램 동작함
```

- [ ] Wireshark를 통해 SQL 쿼리 요청이 평문으로 캡쳐됨
- [ ] 목적지 포트가 `1433`(MSSQL), `3306`(MySQL), `1521`(Oracle) 등 DB와 연결됨
- [ ] 링크 라이브러리 확인 시 `System.Data.SqlClient`, `msado15.dll`, `odbc32.dll` 등 DB 드라이버가 Import Table에 존재함
- [ ] 설정파일 내 `Server=`, `Data Source=`, `Uid=`, `Pwd=` 등 DB 연결 문자열이 존재함

### 3-tier
```
애플리케이션 서버와 연결하며 요청 전송 시 서버가 대신 DB와 통신하여 데이터를 기반으로 응답을 반환하는 방식으로 프로그램 동작함
```

- [ ] Wireshark를 통해 SQL 문이 아닌 특정 요청을 요구하는 데이터 포맷인지 확인함
- [ ] 설정 파일에 `https://api.company.com/v1` 처럼 API 엔드포인트만 존재함
- [ ] 링크 라이브러리 확인 시 DB 드라이버 없음, `WinInet.dll`, `Winhttp.dll`, 소켓 API(`Ws2_32.dll`)만 존재함

## 1.2. 사용 기술/프레임워크 파악 (.NET, C++, Java 등)
```
사용된 언어를 바탕으로 분석 방법을 파악하기 위함
```

### DIE 실행 후 확인
- [ ] `.NET` 문자가 출력되면 `dnSpy` 도구를 사용함
- [ ] 실행 파일이 `.jar` 이거나 DIE 분석 시 `Java` 문자가 출력되면 	`JD-GUI` 도구 사용함
- [ ] 위의 경우가 아닐 경우 `Native`로 판단하며 `IDA` 또는 `Ghidra` 도구 사용함

### 바이너리 포맷 확인
- [ ] DIE를 통해 file type 확인하며 `32bit`/`64bit` 등을 파악하여 아키텍처에 맞춰 도구를 사용함
